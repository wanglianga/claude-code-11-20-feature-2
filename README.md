# 教材检索与引用核查平台

面向出版社编辑与一线教师的教材知识点检索、原文定位与引用核查平台。
解决“整本等长切块导致例题条件被切掉、跨节结论被拼接、同名概念学段前提不同、
新版删除旧例题后引用找不到出处”等问题。系统只做**可解释、可本地复现的词项检索**，
不接入任何外部生成模型，**不会生成教材中不存在的答案**。

技术栈：React 18 + Vite（前端）、Python 3.12 + FastAPI（后端）、PostgreSQL（存储与倒排索引）。

## 1. 核心设计与需求对应

| 需求 | 实现方式 |
| --- | --- |
| 不做等长切块，段落/例题独立 | 章节树解析为 `structural_units`，`paragraph`/`example`/`figure_note` 各自独立成行，保留标题路径与结构边界 |
| 长段按句拆开、保留相邻范围 | `text.split_sentences` 按句/逗号/硬换行切分，保存原文偏移 `sentence_ranges`，稳定段落标识不变，区间完整覆盖且互不重叠 |
| 缺图表/重复标识/缺前提进待修正 | 构建时写入 `parse_issues`（`missing_figure`/`duplicate_id`/`missing_premise`/`chapter_error`），编辑端可逐条处理 |
| 中文二元组倒排索引 | 文档侧建 unigram + 相邻字二元组 + 拉丁整词；查询侧多字 CJK **只取二元组**，单字短词才原字匹配，不放大含义 |
| 全半角/大小写归一化且高亮不错位 | `normalize` 字符级 1:1 映射（不删字符，表情/符号原样占位），保存 `norm_mapping`，命中位置映射回原文偏移后再高亮 |
| 同义词编辑审核 + 查询开始时快照 | 仅 `approved` 词表参与扩展，一次查询期间固定；教师可一键关闭扩展比较结果；扩展不递归 |
| 先过滤教材再 BM25 | 先按学段/学科/书号/版本过滤代次，再算 BM25（k1=1.5, b=0.75），返回每词项 df/idf/贡献分与命中位置 |
| 摘要不跨例题 | 摘要只取命中单元内包含最早命中的那个句子区间，绝不跨单元/跨例题拼接 |
| 稳定排序与翻页不串索引 | 分数降序、平分按稳定 `unit_code`；首次检索生成 `search_sessions` 固定代次集合，翻页必须回传 `session_id` |
| 无命中诚实返回 | 返回实际使用词项（原词/同义词标注）、过滤范围与未命中原因，不悄悄取消学段限制 |
| 现行稿默认、旧版显式开启 | 默认只检索 `active` 版本；勾选后才包含 `deprecated`，结果显示停用原因 |
| 代次隔离构建、齐全后切换 | 每代独立 `index_generations` 空间构建；坏章/缺章则整代 `failed` 不可启用；编辑批准时单事务原子切换 |
| 旧作业不得覆盖新稿 | 批准切换时校验只允许该 ISBN 最大代次的就绪稿，陈旧申请直接拒绝（行锁 `FOR UPDATE`） |
| 引用固定代次与指纹 | 引用保存段落标识、采用文字、SHA-256 指纹与出处；复核时原代次不可访问则诚实失败，绝不从最新结果补段 |
| 逐章构建报告 | 每章记录 `received → parsed → terms → verified` 四阶段状态与数量，坏章保留错误 |
| 目标先修成环先拦截 | Tarjan 强连通分量检测回路，建计划/录目标时指出涉及目标编码（如 `OBJ-CYC-X → OBJ-CYC-Y → OBJ-CYC-X`），不成环才计算 |
| 先修闭包整体补齐 | 所选目标的全部传递先修自动进入候选集；先修未有效覆盖时，即使章节已选也不计覆盖，诊断为“缺先修”，不向未学先修的学生推荐后续章 |
| 未审核命中只作候选 | 目标文本检索出的章节命中登记为 `pending` 候选，教师审核 `approved` 后才进入规划；驳回与候选均不参与选章 |
| 贪心近似选章且不重复计费 | 每轮按「新增覆盖权重 ÷ 新增篇幅」选章；一章覆盖多目标只计一次篇幅；明确标注为近似方案，不称最短阅读路线 |
| 篇幅未知不可自动选入 | `chapter_metrics.reading_length` 为 NULL 的章节绝不自动选入、不当零成本；锁定必读时保留并提示无法核算篇幅 |
| 锁定必读超额保留冲突 | 必读章与已有基础可锁定；必读合计超阅读上限时保留全部必读并告警，不删除必读内容凑可行；已有基础覆盖的目标零增量 |
| 未覆盖逐项可解释 | 每个未覆盖目标区分缺教材/缺先修/预算不足，列出候选章与未选原因，并给出最省章节及“再增加多少字可补齐” |
| 计划快照固定与重算隔离 | 创建时固定教材版本、目标先修图、已审关联、目录篇幅四份快照；重算只用同一组资料，后加关联不影响旧计划 |
| 后台作业可取消、旧结果不覆盖 | 作业带 `job_token` 与取消标志，取消后迟到的旧计算经令牌校验一律丢弃；重算排队期间保留旧选择 |
| 教材停用分级联动 | 未确认计划转 `needs_review` 并取消在途作业；已确认（已发教师）计划保留原出处正文，仅追加更新提示，不自动换正文 |

## 3. 一键启动（Docker Compose）

```bash
docker compose up --build
# 后端与前端：http://localhost:8000
# Swagger UI（可选的接口文档）：http://localhost:8000/docs
```

启动时自动建表并播种全部演示场景（同名异义、新旧稿、缺前提、缺图、重复标识、构建中断，
以及课程阅读规划的 9 个教学目标、1 条先修回路、覆盖审核样本与 6 个计划样本）。
停止并清空数据卷：`docker compose down -v`。

## 4. 本地开发启动（使用容器内预装运行时）

前置：本机 PostgreSQL 已运行，`postgresql://ccdev:ccdev@127.0.0.1:5432/ccdev` 可连。

### 后端

```bash
cd backend
/opt/python-3.12/bin/python3 -m venv .venv
.venv/bin/pip install -r requirements.txt        # 已配置清华镜像
# 首次启动自动建表+播种；AUTO_SEED=false 可关闭
PGPASSWORD=ccdev .venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 前端（开发模式，代理 /api 到 8000）

```bash
cd frontend
/opt/node-22/bin/npm install --cache /tmp/npm-cache   # 若默认 npm 缓存目录不可写
/opt/node-22/bin/npm run dev          # http://localhost:5173
# 生产构建：npm run build，产物在 frontend/dist，后端会自动托管
```

## 5. 验证方式

### 5.1 自动化测试

```bash
cd backend
PGPASSWORD=ccdev .venv/bin/python -m pytest tests/ -q
```

覆盖：归一化位置映射（含表情不错位）、二元组查询语义、分句覆盖、
构建隔离与四类待修正、构建中断整代失败、BM25 贡献可解释与稳定排序、
同义词开关与待审词不生效、无命中诚实返回、翻页固定代次、
引用指纹/漂移/代次退役诚实失败、角色权限、陈旧作业拒绝、坏代次不可启用；
以及规划模块 23 个用例：Tarjan 成环检测与涉及目标输出、先修闭包传递、
一章多目标只计一次篇幅、贪心按权重/篇幅比选章、篇幅未知不自动选入、
锁定必读超额保留冲突、已有基础零增量、未覆盖三因诊断与补齐阅读量、
候选关联审核前不入规划、计划快照重算隔离、取消后旧结果丢弃、
教材停用后已确认计划保留/未确认计划待复核。

### 5.2 手工场景验证（建议路径）

1. **同名异义**：教师登录，检索 `函数`，分别只选“初中”与“高中”，
   高中首条落在“集合 A→B 映射”前提单元，初中落在“变化过程单值对应”单元，两者版本互不串。
2. **新旧稿差异**：默认检索 `汽车行驶` 无命中（新版已删该例题）；
   勾选“显式开启停用旧版”后命中旧版例题，卡片显示停用原因。
3. **同义词比较**：检索 `取值范围`，切换同义词开关，证据栏显示扩展词项（`定义域` 等）及其来源。
4. **无命中诚实性**：检索 `量子纠缠`，页面展示实际词项与过滤范围，明确未生成教材外答案。
5. **原文与例题**：命中卡片 → “跳到原位置”，查看完整例题条件、句子区间与本章相邻单元。
6. **引用核查**：固定引用后到“引用核查”页复核；编辑在“构建监控”退役旧代次后，
   该引用复核返回 `原代次不可访问`，系统不会用新版内容冒充。
7. **构建中断**：编辑端选择物理数据包并勾选“仅提交第13章”，构建结果为 failed，
   逐章报告显示第 14 章未接收，待修正队列出现 chapter_error，该代次无法启用。
8. **陈旧作业保护**：在“版本替代”里尝试用第 1 版回滚现行稿，批准被 409 拒绝，现行稿保持第 2 版。
9. **规划·一章覆盖多目标**：打开“阅读规划”，查看「样本1」，CH19 一章覆盖 3 个目标但只计 3000 字一次篇幅，全部目标覆盖。
10. **规划·依赖回路**：“目标与覆盖审核”页顶部红色回路提示 `OBJ-CYC-X → OBJ-CYC-Y → OBJ-CYC-X`；
    新建计划勾选任一回路目标提交，接口返回 422 并列出涉及目标。
11. **规划·锁定超额**：查看「样本3」，预算 1000 字却保留 4000 字必读章，
    页面显示超额告警且不删除必读；任一未覆盖项可展开看到候选章、未选原因与“再增加多少字可补齐”。
12. **规划·缺教材/缺先修/篇幅未知**：「样本4」展开导数两目标，先修目标诊断为缺先修并给出补齐字数；
    「样本5」的 OBJ-NM 只有未审核候选且 CH20 篇幅未知，诊断为缺教材，不产生任何选章。
13. **规划·停用联动**：编辑在“构建监控”退役旧代次后，固定该版本的未确认计划变为“待复核”，
    已确认计划状态不变、出处保留，仅在告警与事件留痕中提示更新。
14. **规划·取消与快照**：对计算中计划点“取消计算”，状态置为已取消且迟到结果不覆盖当前选择；
    调整预算后“按同一组已审资料重算”，事件留痕可追溯，计划不会采用创建之后新增的关联。

## 6. 实际执行过的验证结论

以下均为本次开发中真实执行的结果（2026-11）：

- `pytest tests/ -q`：**64 passed**（独立临时 schema，不污染开发库；含规划模块 23 个用例）。
- 前端 `npm run build`：构建成功，产物 `dist/`（JS 约 211 KB / gzip 69 KB）。
- 启动 uvicorn 后用 curl 完成端到端：登录 → 检索（7 条命中、固定代次 [2]）→
  翻页代次不变 → 原文定位（含相邻单元与结构化例题条件，如 EX-19-4 返回 3 条前提）→
  跨代次访问旧例题被 409 拒绝 → 创建引用 → 复核 ok →
  无命中返回真实词项与范围 → 编辑端 4 个代次（ready/archived/failed）与 4 类待修正 →
  SPA 根路径与静态资源均 200。
- 规划端到端（真实后台线程作业）：播种的 6 个计划样本全部 `ready`；
  回路目标建计划返回 422 且 `detail.cycles` 列出涉及目标；
  导数计划对 OBJ-D1 诊断“预算不足（再增 1000 字）”、OBJ-D2 诊断“缺先修”；
  对已就绪计划取消返回明确 422（不破坏数据），同快照重算后恢复 ready；
  锁定超额计划保留 4000/1000 字冲突并带告警；取消语义与停用联动由 pytest 确定性覆盖。
- OpenAPI 3.1 文档可由 FastAPI 生成，共 32 个接口路径，`/docs` 提供 Swagger UI。
- 本容器未安装 Docker CLI，**镜像未在本机实际构建**；Dockerfile/compose 已按标准多阶段写法提供，
  新增模块均在 `COPY backend/app`、`COPY frontend/` 范围内且未新增依赖，
  请在具备 Docker 的环境执行第 3 节命令验证。

## 7. 边界说明

- 只接收项目自带 JSON 章节树、UTF-8 正文与图表说明，不处理扫描图片。
- Redis 未被使用：倒排索引与 BM25 统计全部落在 PostgreSQL，无需额外组件。
- 检索是纯词项匹配，无法覆盖所有语义改写；此时系统如实显示未命中与实际查过的范围。
- 阅读规划的选章是确定性贪心**近似**算法（权重/篇幅比逐轮择优），不保证全局最优，
  页面与接口均明确不标注为“最短阅读路线”；只使用教师已审关联与已登记篇幅，
  不会根据检索候选或未知篇幅章节自动生成选择。
- 规划只在计划创建时的快照资料上计算；教材改版后需人工复核或新建计划，
  系统不自动把已发计划的出处替换成新版正文。
